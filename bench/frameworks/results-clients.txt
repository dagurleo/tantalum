redis-py 7.4.0 (sync and asyncio; no cluster, modules, TLS, replicas or cloud), Predis 3.6.1 (phpunit's
default groups), redis-rb 6.0.0 (redis and distributed), ioredis 5.11.0 (unit and functional), phpredis 6.3.0

That's 99 of 10,530, and 81 of them need one of the first three: something that isn't here. Each of the other
18 was read: WAITAOF's (5) turn the log on with CONFIG SET appendonly, which needs --aof at the start here;
LATENCY HISTOGRAM (5) and INFO commandstats (3, counting phpredis' testConfig) need per-command statistics, which
would cost every command, so they wait for a measurement; BGSAVE and BGREWRITEAOF (3) refuse without --snapshot or
--aof, where Redis saves to its default; COMMAND LIST (1) expects over 300 commands, and there are 225;
OBJECT IDLETIME (1) is always 0, as no access time is kept per key.

Both servers now run with DEBUG allowed, as the libraries' own setups have it, so 21 more redis-py tests pass on
the control than in the table below. Tests of Redis 7.4 and 8 commands (HEXPIRE and the like) fail on the control
too, so they aren't here. Five node-redis tests (Sentinel's) and one of phpredis' pass on the control and never ran
on Tantalum, and aren't counted. redis-rb won't start without a Unix socket, so its Tantalum run has socat in front
of the port: Tantalum has no Unix sockets, and that's in no count above. node-redis's server options are dropped for
Tantalum but for --requirepass and --enable-debug-command.

Besides these suites, tools/admin-diff.py sends 3,358 commands and checks to Redis 7.2.4 and to Tantalum, with no
differences: every command's COMMAND INFO and DOCS in both protocols, every setting's default, what each setting says
to bad values, `~` trims with nodes of other sizes, the latency monitor, MONITOR's lines and SLOWLOG's entries.
